## 1. 结论先行

- DSH 插件 = **npm 包 + Cordis 插件**，通过 package.json 里的 `dsh.bundle.patch` 字段声明自己是"bundle（补丁层）"。
- 安装插件只需一条命令：`dsh plugin --profile web add <包名或本地路径>`（该命令内部是 pnpm 转发器）。
- 安装后插件自动进入 profile 的 `dsh.profile.bundles` 层叠栈，下次启动 `dsh web` 即生效。
- 视觉识别已有现成参考实现：`dsh-plugin-deepeye`（npm，源码已下载到 `reference/dsh-plugin-deepeye/`）。

## 2. 概念：profile / bundle / patch 三层结构

```
$DSH_HOME/profiles/<name>/          # profile 目录（本机 DSH_HOME = C:\Users\LIPSTICK\.dsh）
├── package.json                    # 依赖 + dsh.profile.bundles 层叠清单
├── cordis.patch.yml                # 用户自己的 patch 层（覆盖配置）
└── node_modules/                   # pnpm 安装的插件
```

配置树叠加顺序（空根起步）：
1. `dsh.profile.bundles` 里各 bundle 的 patch（按顺序）
2. profile 的 `cordis.patch.yml`
3. home 级 `$DSH_HOME/cordis.patch.yml`
4. 命令行 `--patch <file>` 额外叠加

用 `dsh --profile web --dump-config` / `--dump-default-config` 可查看组合结果。

## 3. 如何安装 / 导入插件（用法）

```bash
# 从 npm 安装
dsh plugin --profile web add dsh-plugin-deepeye

# 本地开发（在插件源码目录的上一级执行，相对路径会被锚定到当前目录）
dsh plugin --profile web add ./dsh-plugin-deepeye

# 等价于 pnpm 转发：add / remove / update / install 都可用
dsh plugin --profile web remove dsh-plugin-deepeye
dsh plugin --profile web update dsh-plugin-deepeye
```

机制（源码 `lib/plugin-*.js` 验证）：
- profile 不存在时首次使用自动初始化（web/headless 有内置模板）。
- pnpm 装完后执行"对账"：凡 package.json 声明了 `dsh.bundle.patch` 的依赖，自动追加进 `dsh.profile.bundles`；未声明的当普通依赖（有警告）。
- git 安装的插件需要构建脚本时，须在 profile 的 `pnpm-workspace.yaml` 的 `allowBuilds` 里放行。

## 4. 如何开发一个插件（结构）

### 4.1 包结构（bundle = 补丁层 + Cordis 插件本体）

```
my-dsh-plugin/
├── package.json          # main 指向编译产物；声明 dsh.bundle.patch
├── cordis.patch.yml      # patch：把插件插入组合树
├── src/index.ts          # Cordis 插件：export { Config, apply, inject, name }
└── lib/                  # 构建产物（tsdown / tsup 均可）
```

`package.json` 关键字段（参考 deepeye）：

```jsonc
{
  "name": "my-dsh-plugin",
  "type": "module",
  "main": "lib/index.mjs",
  "peerDependencies": {
    "@deepseek-ai/cordis": "^4.0.1",        // Cordis 运行时
    "@deepseek-ai/dsh-tools": "^0.1.0-rc.6" // 工具注册 API (defineTool)
  },
  "dependencies": {
    "@deepseek-ai/schemastery": "^3.18.1"   // 配置 schema
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" }  // ← 声明自己是 bundle
  }
}
```

`cordis.patch.yml`（把插件 id 插入组合树）：

```yaml
- insert:
    - id: my-vision
      name: 'my-dsh-plugin'
```

### 4.2 插件本体（Cordis 插件，src/index.ts 骨架）

```ts
import { defineTool } from "@deepseek-ai/dsh-tools";
import z from "@deepseek-ai/schemastery";

export const name = "my-vision";               // 与 patch 里的 id 一致
export const inject = ["tools", "systemPrompt"];

export const Config = z.object({
  apiKey: z.string().default(""),
  model: z.string().default(""),
});

export function apply(ctx: any, config: z.infer<typeof Config>) {
  // 可选：注入 system prompt，让模型知道何时用视觉工具
  ctx.systemPrompt.section({
    name, order: 150,
    text: () => "你有视觉工具 vision_describe，用户问图片时使用它。",
  });

  // 注册工具（模型可调用）
  ctx.tools.register(defineTool({
    name: "vision_describe",
    description: "描述图片内容，支持本地路径 / http(s) URL / data URI",
    parameters: {
      image_source: { type: "string", required: true, description: "..." },
    },
    output: {
      schema: { type: "string" },
      render: (_args, value) => [{ type: "text", text: value }],
    },
    presentCall(args) { return { card: "generic", title: `看图: ${args.image_source}` }; },
    presentResult(args, result) { return { card: "generic", content: result.content }; },
    async execute(args, exec) {
      // 调视觉模型（OpenAI-compatible 端点即可），返回文字
      return "图片分析结果：...";
    },
  }));
}
```

要点：
- `defineTool` 的 execute 里 `exec.signal` 是中止信号（AbortSignal）。
- `presentCall` / `presentResult` 控制 Web GUI 里的卡片展示（返回 `{card, title, kind, locations, content}` 等）。
- 配置由 schemastery schema 声明，用户可在 profile 的 `cordis.patch.yml` 按 `id` 覆盖：

```yaml
# %USERPROFILE%\.dsh\profiles\web\cordis.patch.yml
- id: my-vision
  config:
    apiKey: !!js process.env.DASHSCOPE_API_KEY
    model: qwen-vl-max
```
